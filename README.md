# Telegram-бот «Сопровождающий сеанса массажа»

Методический ассистент массажиста: выбираете протокол — бот ведёт по этапам сеанса (поглаживание → растирание → разминание → вибрация → завершающее поглаживание), показывает приёмы этапа и сам переключает этапы по таймеру.

**Стек:** Node.js 20 · Vercel serverless (Hobby) · Telegram webhook · Upstash Redis · Upstash QStash (отложенные сообщения `Upstash-Delay` — «будильник» переходов, переживающий cold start).

⚠️ Бот — методический помощник для дипломированного специалиста, а не медицинское устройство. Противопоказания в карточках — памятка, не замена консультации врача.

## Возможности

- Каталог из 14 протоколов (`data/protocols.json`) по 4 категориям: классический по зонам (ШВЗ, спина, поясница, ноги, руки, живот, голова/лицо), общий и оздоровительный (общий классический, антистресс), косметологические (лимфодренажный, антицеллюлитный, медовый), спортивный (восстановительный, предварительный).
- Три режима длительности: Сокращённый ×0.7 / Стандартный ×1.0 / Расширенный ×1.4 (округление этапа до 0,5 мин, минимум 1 мин).
- Активный сеанс: одна карточка с этапом, приёмами, подсказкой и временем перехода; кнопки «Пауза», «Пропустить этап», «Завершить». Таймерные переходы приходят отдельным сообщением со звуком (уведомление), старая карточка удаляется.
- Пауза/возобновление с пересчётом остатка, пропуск этапа, досрочное завершение — через `epoch`-инвалидацию: устаревшие QStash-сообщения отбрасываются идемпотентно.
- Справочник приёмов (`data/techniques.json`), общие противопоказания, история последних 50 сеансов, настройки (длительность по умолчанию, звук: всегда / ночью тихо 22:00–08:00 по Минску / без звука).

## Деплой

1. **Бот:** создайте бота у [@BotFather](https://t.me/BotFather), получите `TELEGRAM_BOT_TOKEN`.
2. **Upstash:** на [upstash.com](https://upstash.com) создайте Redis-базу (возьмите `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`) и включите QStash (возьмите `QSTASH_TOKEN`).
3. **Vercel:** импортируйте репозиторий (план Hobby). В настройках проекта задайте переменные окружения из `.env.example`:
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` (произвольная секретная строка), `APP_URL` (например `https://<проект>.vercel.app`, без слэша в конце), `QSTASH_URL` (региональный endpoint, например `https://qstash-eu-central-1.upstash.io`), `QSTASH_TOKEN`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `CRON_SECRET` (произвольная секретная строка).
4. **Регистрация webhook** (разово, после деплоя):

   ```
   https://<проект>.vercel.app/api/telegram?setup=<TELEGRAM_WEBHOOK_SECRET>
   ```

5. Напишите боту `/start`.

Опционально: GitHub Actions-пингер (`.github/workflows/ping.yml`) раз в 10 минут дергает `/api/health` — задайте переменную репозитория `APP_URL` в Settings → Actions → Variables.

## Как работают таймеры (ядро)

Функция Vercel Hobby живёт ≤10 секунд, поэтому «спать» весь сеанс нельзя. При старте сеанса `lib/session.js` публикует в QStash **всю цепочку переходов** сразу: для каждого перехода на этап `i+1` — сообщение на `/api/session/advance` с заголовком `Upstash-Delay = сумма длительностей этапов 0..i` и `Deduplication-Id = {sessionId}:{epoch}:{targetStageIndex}`. QStash хранит и доставляет сообщения сам (с ретраями), «будя» инстанс HTTP-запросом.

Пауза/пропуск/стоп увеличивают `epoch` сеанса в Redis — все ранее запланированные сообщения перестают проходить проверку `isValidAdvance` (`lib/chain.js`) и молча отбрасываются с ответом 200. При возобновлении планируется новая цепочка от остатка текущего этапа.

Endpoint `/api/session/advance` защищён секретом `CRON_SECRET`, который передаётся в теле каждого отложенного сообщения.

## Структура

```
api/
  telegram.js          # webhook: команды, callback-кнопки, ?setup=-регистрация
  session/advance.js   # переходы этапов (вызывается QStash)
  health.js            # health-check для пингера
lib/
  telegram.js  redis.js  qstash.js       # интеграции (fetch, без фреймворков)
  protocols.js                            # загрузка+валидация каталога, режимы длительности
  chain.js                                # чистая логика цепочки и идемпотентности (тестируется)
  session.js                              # старт/переходы/пауза/пропуск/стоп
  render.js  keyboards.js                 # тексты карточек и инлайн-клавиатуры
data/
  protocols.json       # каталог 14 протоколов — единственный источник правды
  techniques.json      # справочник приёмов
test/                  # node --test
```

Отличие от структуры в ТЗ: `start/control/finish` реализованы не отдельными HTTP-endpoint'ами, а функциями `lib/session.js`, вызываемыми из webhook — Telegram присылает нажатия кнопок только на `/api/telegram`, и лишние внутренние HTTP-переходы лишь тратили бы вызовы функций и время.

## Добавление нового протокола

Добавьте объект в `data/protocols.json` (структура — раздел E ТЗ; длительности в секундах). Правила, проверяемые тестами и при загрузке (невалидный протокол исключается из каталога с логом):

- `id` уникален, `category` ∈ `classic_zones | general | cosmetic | sport`;
- сумма `durationSec` этапов равна `baseDurationSec`;
- каждый этап имеет ≥1 приём;
- первый этап — поглаживание; последний — тоже поглаживание, кроме протоколов с `"finalEffleurage": false` (например, спортивный предварительный, который по методике завершается потряхиванием).

## Тесты

```bash
npm test
```

Покрывают: валидацию всех 14 протоколов, fail-safe исключение невалидных, масштабирование длительностей, накопительные задержки QStash-цепочки, идемпотентность `advance` (epoch, чужой сеанс, дубли).

## Лимиты бесплатных тарифов

Один сеанс = 3–8 QStash-сообщений (по числу этапов). QStash free — 500 сообщений/день (~60–100 сеансов/день), Upstash Redis free — 500K команд/мес, Vercel Hobby — таймаут функции 10 с, некоммерческое использование. Для практики одного мастера — запас многократный; при монетизации перейти на Vercel Pro.
